## Selected boundary

One .NET 10 WPF executable with CommunityToolkit.Mvvm; no database/service/event bus. An unelevated GUI reads run artifacts and starts read-only detection. A fixed elevated operation from a protected installation launches the existing PowerShell 5.1 scripts in separate processes. Never elevate from a portable user-writable copy; portable distribution supports review/detection, while privileged execution requires installation under administrator-owned Program Files with validated ACLs and a trusted code integrity anchor. If this cannot be proven on Windows CI, remediation remains disabled, not silently downgraded. The application should surface existing HTML in the default browser, not duplicate reporting.

Current Microsoft references: [WPF is Windows-only](https://learn.microsoft.com/en-us/dotnet/desktop/wpf/overview/?view=netdesktop-10.0), [CommunityToolkit.Mvvm supports WPF](https://learn.microsoft.com/en-us/dotnet/communitytoolkit/mvvm/), [self-contained publish](https://learn.microsoft.com/en-us/dotnet/core/deploying/), [shell elevation and redirected streams are distinct modes](https://learn.microsoft.com/en-us/dotnet/api/system.diagnostics.processstartinfo.useshellexecute?view=net-10.0), [PowerShell signing](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.core/about/about_signing?view=powershell-5.1). Validate packaging and ACL behavior on real Windows runners; Linux compilation does not prove WPF runtime behavior.

## Phase gates

0: audit + contract + validated OpenSpec. 1: synthetic four-view WPF build/navigation only. 2: real read-only detector, zero/multi/error/failure tests. 3: shared pipeline noninteractive status and CLI regressions. 4: protected all-instance approval/removal refusal tests. 5: attended scanners/AV status. 6: verification, report and share. 7: recovery and portable/protected packaging. Each gate needs its own tests and integration review before the next starts; no phase can claim full live remediation from CI.
